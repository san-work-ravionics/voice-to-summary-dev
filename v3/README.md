# v3 — Checklist-based coverage check

Part of the [voice-to-summary](../README.md) progression. Builds on [v2](../v2/README.md)'s context-aware summarizer by adding a fixed **checklist** of expected topics, so the summary reports what was and wasn't actually discussed.

Same recording/transcript as v1/v2 — only the summarization step changes.

## What's new

`src/checklist.py` defines a fixed `CHECKLIST` of topics this kind of status meeting is expected to cover:
- Onboarding flow status
- Payments integration status
- Design updates (e.g. dark mode)
- Legal / privacy approval
- Analytics instrumentation
- Budget or cost impact
- Next meeting / follow-up schedule

Everything except **budget/cost impact** is actually discussed in the dummy dialogue — that one is left out on purpose, so the "Not covered" path is demonstrably exercised, not just theoretical.

`src/summarize.py` still uses the local LLM for the Topic/Key Points/Decisions/Actions brief (same as v2), then appends a 5th Markdown section, `## Checklist Coverage`. That section is **not** generated by the LLM — three different LLM-based framings were tried (all 7 items in one call, one call per item against the transcript, one call per item against the brief) and each got 2-3 of 7 items wrong, sometimes even contradicting its own stated reasoning. Each checklist item instead carries a few keywords (`src/checklist.py`), and coverage is decided by a plain keyword match against the transcript, quoting the matched sentence as evidence — deterministic and correct by construction for this known content, rather than a small model's unreliable judgment call.

## Run

```bash
python v3/src/main.py
```

Writes `output/recording.wav`, `output/transcript.txt`, and a single `output/summary.txt` with all 5 sections. Pass `--regenerate` for a fresh recording.
